Existing Go 1.27.1 build, shared auth pool, safe maps, handshake version override,
passkey flow, sessions, database configuration and payload response envelope are retained.
No new infrastructure, routes or database reset. Latest and the deployed compose digest are unchanged.

Upstream: https://github.com/evolution-foundation/evolution-go/pulls
Candidate provenance SHAs are recorded in the audit delivered before this release.

Validation runs in GitHub Actions: dependency verification, build, vet, all tests,
race detector, isolated PostgreSQL container smoke/start/restart, then amd64/arm64
publication. Publication is blocked when validation fails.

Production qualification after publication still requires real WhatsApp checks:
session/reconnect/QR, inbound and outbound text/media, animated sticker, edit/revoke,
Brazilian contacts, avatar/LID, mentions and webhook delivery. CI uses isolated
databases and never connects to the production WhatsApp session or database.

Revision 2 preserves HTTP 500 for missing/private avatar responses, but returns
stable safe codes PROFILE_PICTURE_NOT_SET and PROFILE_PICTURE_PRIVATE. Revision 1
sanitized these known conditions into a generic query error, preventing consumers
from distinguishing unavailable pictures from transport/store failures. Wrapped
internal error details remain hidden. ATENDA treats those explicit conditions as
normal absence and retains any existing cached avatar.

Revision 3 decrypts new community reactions and comments through the owning
whatsmeow client's DecryptReaction/DecryptComment methods, before JID changes.
Nonce, target and secret-store guards prevent malformed inputs; a five-second
context bounds decryption. Failures preserve the encrypted envelope and mark
decryptFailed. Authenticated fixtures exercise the real crypto and webhook path.
No historical replay, database reset or pairing change is performed.
